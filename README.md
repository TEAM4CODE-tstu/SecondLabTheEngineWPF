# Лабораторная работа №2 — «Движок слабейшего предусловия (wp) для последовательности и if»

## Что это?
Данное приложение представляет собой интерактивную настольную систему для демонстрации концепции **исчисления предикатов** и **формальной верификации программного обеспечения** (анализ программ как преобразователей предикатов) в пользовательских интерфейсах. 

Проект наглядно показывает, как на основе:
* Заданного постусловия (**Post**)
* Исходного кода фрагмента (последовательности присваиваний и ветвлений `if-else`)

Автоматически вычисляется, визуализируется и проверяется **наименьшее предусловие** (*Weakest Precondition / wp*), формируя итоговую **триаду Хоара** для строгого доказательства корректности алгоритма.

## Описание
В качестве сквозного сюжета для бизнес-логики выбран модуль **«Логистика и учет грузов»**. Приложение содержит три взаимосвязанные операции статического анализа:
* **Контроль перегруза (Мин/Макс)** — математическое доказательство выбора критических весовых границ отдельных грузов в партии.
* **Оптимизация погрузки** — анализ корректности цепочек распределения или упорядочивания объектов по весовым категориям.
* **Расчёт общей массы рейса** — верификация последовательностей агрегации суммарного веса прибывших грузов.

Если в рамках первой лабораторной работы контракты проверялись динамически во время выполнения (Runtime), то в текущей версии фокус полностью смещен на **статический анализ кода фрагментов** (Static Analysis). 

На основе заданного постусловия алгоритма приложение автоматически рассчитывает **наименьшее предусловие (wp)** с помощью исчисления Дейкстры. Результаты пошагового вывода формул, автоматический контроль математической определенности и итоговая триада Хоара мгновенно отображаются пользователю, демонстрируя математическую гарантию безопасности выполнения кода еще до его фактического запуска и без ввода конкретных числовых параметров.

## Архитектура проекта и описание классов
Приложение спроектировано по принципам многослойной чистой архитектуры с четким разделением ответственности между слоем вычислений домена и слоем представления по паттерну **MVVM**.

### 1. Слой логики и предикатов (`DomainClassLibrary`)
Содержит изолированные от интерфейса классы символьных вычислений и парсинга абстрактного синтаксического дерева программных фрагментов:
* **`WpEngine.cs`** — математическое ядро системы. Реализует обратный пошаговый анализ Дейкстры (снизу вверх). Автоматически распознает операторы присваивания (`:=`) и ветвления (`if-else`) с помощью регулярных выражений, выполняет символьную подстановку переменных \(R[x \leftarrow e]\) и налету формирует предикаты условий определенности (проверка деления на ноль).
* **`WpPresets.cs`** — статический справочник демонстрационных сценариев. Содержит готовые структурированные наборы данных для пресетов, связывая их со сквозным сюжетом учета грузов.
* **`WpResult`** — доменный класс-контейнер (DTO) для передачи результатов анализа (коллекция промежуточных шагов, финальная строка формулы) в слой представления.

### 2. Слой интерфейса и связывания (`GoodsLogistics`)
Реализует графическое отображение и интерактивное управление бэкенд-движком:
* **`FragmentConstructorViewModel.cs`** — управляющий MVVM-диспетчер вкладки ЛР-2, унаследованный от общей архитектурной базы `OperationViewModelBase`. Объявляет реактивные свойства (`PostText`, `CodeText`, `FinalWp`) для двусторонней привязки к полям ввода XAML, обрабатывает события нажатия кнопок через команды `ICommand` (`RelayCommand`), трансформирует сырые технические логи движка Дейкстры в форматированные объекты списков интерфейса и генерирует отчет триады Хоара.
* **`WpStepItem`** — вспомогательная модель представления для атомарного хранения элементов пошагового трейса (разрезает строку на имя оператора и текущее логическое условие) для красивого табличного вывода.
* **`FragmentConstructor.xaml`** — пользовательское представление (`UserControl`), задающее двухколоночную модульную сетку интерфейса, стили интерактивных кнопок-ссылок и шаблоны динамических списков `ItemsControl`.

## Как пользоваться приложением
1. **Переключение на WP-движок:** В верхнем меню приложения перейдите на вкладку **«Конструктор фрагмента»**.
2. **Использование демонстрационных пресетов:** На левой панели в блоке «Пресеты» кликните по любому из трех встроенных сценариев («Max из двух», «Квадратное уравнение» или «Последовательность»). Поля кода фрагмента, краткой формулы цели (Post) и её текстового пояснения автоматически заполнятся заготовленным шаблоном.
3. **Редактирование спецификаций:** При необходимости вы можете вручную изменить текст кода фрагмента или математическое выражение в поле «Цель (Post), кратко».
4. **Запуск статического анализа:** Нажмите кнопку **«Рассчитать wp»** на левой панели.
5. **Анализ результатов вычисления:** 
   * В блоке **«Шаги:»** отобразится детальный интерактивный лог трансформации предикатов при протяжке формулы через каждый оператор снизу вверх (от конца кода к началу).
   * В блоке **«Итоговое wp:»** выведется сгенерированное символьное выражение наименьшего предусловия.
   * В блоке **«Условия определённости:»** отобразятся автоматические нотации движка о безопасности кода (например, при наличии знака деления `/` движок сам внедрит в итоговое выражение защиту от нуля `&& (знаменатель != 0)`).
6. **Формирование триады Хоара:** Нажмите кнопку **«Показать триаду»**. В самом низу формы сгенерируется готовое академическое доказательство в строгом математическом формате `{Pre} Код {Post}` для быстрого переноса в отчет.
